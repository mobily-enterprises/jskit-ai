# Changelog

## Unreleased

- **Breaking.** `agentResources()` declares its five tables with ownership `system`, where they were `public`: a run, goal, summary or command belongs to a conversation, and only the stores, in the owner's system context, read and write them. A handle call with a request's context, a job context derived from the system context (`forWorkspace`, `forUser`, `forWorkspaceUser`) or none throws `SystemContextRequiredError` before any statement; as `public` it reached every workspace's rows, an application's added `workspace_id` or `user_id` columns notwithstanding. Requests reach the rows through the stores (`goals.openGoal`, `runs`, `summaryStore`), with the conversation the application resolved for the caller.
- **Breaking (data-access redesign).** `./server` no longer exports `currentTodos(knex, conversationId, tables)` or `PLANNING_TABLES`: the `planning` store the application passes answers `currentTodos(conversationId)`, and the agent tables are the table resources `agentResources()` describes.
- `@jskit-ai/database-runtime` and `@jskit-ai/resource-runtime` are peer dependencies, required and at the same versions, where they were dependencies: its tables need them, and the app holds one copy of the table runtime that every package shares, as it does the kernel. npm installs a required peer as it installed the dependency, so an app installs the same packages and versions; a release whose versions disagree now fails the install with ERESOLVE instead of nesting a second copy.
- Every factory fails at startup when called the earlier way, naming what to pass instead: `createRuns`, `createGoals`, `createSummaries` and `createCommands` refuse `knex`, `tables` and `table`, and assert the agent-table handles they read through (`resources.agentRuns`, `agentGoals`, `agentSummaries` and `agentSummaryQueue`, `agentCommands`) and `systemContext`, pointing to the feature that owns `agentResources()`; `defaultTools` and `planningTools` refuse `knex` and `tables`, and they and `planningNotes` check that `planning` has `currentTodos`, `mergeTodos`, `jobNotes` and `setJobNotes`. A missing handle used to fail at the first statement, and `planningNotes(knex, ...)` on the first turn.
